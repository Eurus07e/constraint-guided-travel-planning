# Experiment protocol and run recovery

## Historical evidence

`results/frozen/manifest.json` binds predictions, sample IDs, historical outcomes,
expected metrics and database hashes. `scripts.replay_frozen` re-scores all 13
methods. `scripts.analyze_evidence` computes paired bootstrap intervals (20,000
resamples, seed 20260904) and exact two-sided McNemar tests.

The intervals are conditional on frozen predictions on a development split.
They do not estimate model-generation variance. Component contrasts use separate
stored model generations, are exploratory and are not causal component effects.

## Independent replications

Configure `OPENAI_API_KEY`, `OPENAI_API_BASE` and `MODEL_NAME` in the environment.
Run these commands once for each provider/model:

```bash
python -m scripts.run_replication --dry-run
python -m scripts.run_replication --limit 3
python -m scripts.run_replication
```

`configs/replication.json` specifies three independent repeats on all 180 labeled
validation tasks, four worker processes, a 4,096-token per-response limit and at
most five request attempts per method/case. A 64-token preflight stops batching
on authentication/model-access failure. A distinct repeat ID is included in every
cache identity; requests from another repeat are never reused.

Each case/repeat generates a fresh Direct seed. Self-Refine reuses that exact
seed. Selector, deterministic repair, CC-MAR and the seeded loop receive that
same Direct seed plus the same published historical Program seed. This fixed
Program seed was generated with the historical model; this is transfer of repair
behavior, not a claim that all seeds were generated by the tested provider.

CC-MAR uses one round (up to four specialists and one critic); the seeded loop
uses two rounds and three candidate slots. A common upper request bound is not
identical actual compute. Compare measured incremental requests/tokens and add
the shared Direct seed cost when reporting end-to-end cost. The original Program
seed generation cost is not available. Provider monetary costs are not inferred
without a dated pricing table.

## Checkpoints and failures

Main runners place output under `runs/<strategy>/<configuration fingerprint>/`.
Set `OUT_ROOT` to select another base; it still receives a fingerprint directory.
The manifest includes model settings, audit version, code hashes, input hashes,
endpoint and repeat ID. Changing any of those creates a separate run. No secret
is written to the manifest. An explicit `SUBMISSION_FILE` cannot overwrite a
file owned by a different fingerprint.

Re-running the same command resumes completed cases. Interrupted/corrupt files
are regenerated using the same run's request cache. Failed cases have status
`failed`, remain visible in the denominator and can be retried. A replication
with failed cases is marked incomplete. Never combine incomplete and complete
runs without reporting the failures.

```bash
python -m scripts.summarize_requests runs/<strategy>/<fingerprint>/requests.jsonl
```

`TP_MAX_REQUESTS` is an optional hard bound on actual attempts; 401/403 failures
are not retried. Transient errors receive bounded backoff. Cache hits are counted
separately from network requests. Checkpoints use atomic replacement.

## Audit and evaluation boundary

New runs use `strict-v2`. `scripts.reproduce` explicitly uses `legacy-v1`; set
`TP_AUDIT_VERSION=legacy-v1` when studying a historical implementation. Both are
internal audits; neither calls the final scorer during candidate selection.
The strict version was developed using validation failures, so its calibration
cannot be interpreted as held-out performance.

Full and subset evaluation share `evaluation.protocol`. Historical day aliases
and plan-length quirks retain the released scorer's behavior; `schema_ok` records
whether a prediction meets the stricter new input format. Empty or unscoreable
plans fail with their applicable constraints retained in Micro denominators.
The full entry point requires every ID; the subset entry point reports its exact
sample count. Duplicate/out-of-range IDs and invalid container types are errors.

## Archived Qwen runs

Three July 2026 runs each cover the same 997 test queries; IDs 1, 453 and 885 were
excluded in the stored experiments. Query-derived constraints are used because
private test annotations are unavailable. The adapter exactly recovers all four
checked fields on 180 labeled validation examples; this does not prove accuracy
on unseen test wording. These results are proxy test evaluation.

The stored Direct Final Pass percentages are 9.7292, 10.3310 and 9.8295; deterministic
repair gives 29.6891, 29.1876 and 28.6861. Response files differ across runs, but
provider request IDs were not retained and run 1 has no usage metadata. The
archived files are not substitutes for new experiments. New September 2026
provider preflights both returned HTTP 401; their batches were not dispatched.
